## Проверенное подключение конкретного PW4

13 ноября 2026 выполнен вход по SSH через USB с ключом, `id` вернул uid=0.
Установлен USBNetLite 1.0.M для KindleHF через MRPI. Wi-Fi-доступ SSH и парольный
вход отключены в конфигурации USBNetLite. Приватный ключ хранится локально
в `%LOCALAPPDATA%\KindleLite\USBNetLite`, отдельно от репозитория.

Windows первоначально назначила USB-устройству VID_0525/PID_A4A2 драйвер usbser.
После установки подписанного Microsoft пакета RNDIS из Microsoft Update Catalog
устройство определилось как Ethernet 2. Адрес ПК 192.168.15.100/24 настроен
в ActiveStore, адрес Kindle 192.168.15.244. После перезагрузки Windows настройка
адреса ПК может потребовать повторения.

Для входа из PowerShell используйте `scripts/kindle-ssh.ps1`. Для возврата к
режиму диска используется установленный скрипт KindleLite-USB-Toggle на книге.
Одновременно доступ к диску D: и это USB-соединение не проверялись.

Наблюдаемые характеристики устройства — Linux 4.1.15-lab126, ARMv7, CPU part
0xc09, Hardware Freescale i.MX6 SoloLite, MemTotal 502388 kB. Графическая
ARM-оболочка проекта ещё требует реализации и сборки.

Аппаратный этап не завершён. Здесь нет установщика, автоматической прошивки или команды остановки Amazon framework.

## До запуска на устройстве

1. Вручную сверить модель и точную FW в Settings. Сохранить резервную копию пользовательского USB-раздела и экспортировать важные книги/заметки штатными средствами. Копия USB-раздела не является резервной копией firmware или средством восстановления загрузчика.
2. Пройти актуальный [wizard KindleModding](https://kindlemodding.org/jailbreak-wizard.html) самостоятельно. Не выполнять jailbreak только потому, что 5.16.7 ниже порога WinterBreak. Отдельное подтверждение пользователя обязательно перед потенциально опасной операцией.
3. Только если внешний код уже можно безопасно запускать, вручную скопировать и выполнить `tools/probe-kindle.sh` в уже доступной shell-сессии. Скрипт только читает систему; способ получения shell здесь не предполагается. Не публиковать полный серийный номер и сетевые данные.
4. Подобрать совместимые toolchain и sysroot, проверить ELF interpreter, CPU attributes, GLIBC/GLIBCXX symbol versions относительно устройства. Общий дистрибутивный armhf compiler не доказывает совместимость.

## Кросс-сборка

В WSL2/Linux после отдельной настройки окружения:

```sh
export KINDLE_TOOLCHAIN=/absolute/path/to/compatible/toolchain
export KINDLE_SYSROOT=/absolute/path/to/confirmed/sysroot
cmake -S . -B build-arm -DCMAKE_TOOLCHAIN_FILE=cmake/kindlehf.cmake -DBUILD_TESTING=OFF -DCMAKE_BUILD_TYPE=MinSizeRel
cmake --build build-arm
```

Это конфигурация для переносимого ядра и CLI; Win32-симулятор и браузер не входят в Linux targets. Команда не создаёт графическую оболочку Kindle. Toolchain file ожидает triplet arm-linux-gnueabihf; для другого совместимого SDK имена компиляторов нужно явно адаптировать. Файл проверяет наличие loader, но не доказывает совместимость SDK. Эта sysroot-конфигурация ещё не проверена. Альтернативная статическая сборка CLI и тестов с musl через scripts/build-arm.ps1 проверена на PW4, результаты приведены в validation.md.

## Перенос и откат

Пока допустим только будущий тестовый CLI в отдельной папке пользовательского раздела после проверки бинарника и ручного согласия. Конкретный launcher выбирается по состоянию jailbreak и актуальной инструкции upstream. Не предлагать KUAL вместо KUALA автоматически. Нет autostart и модификации /etc, ядра или bootloader.

До будущего GUI-теста нужны отработанный выход, восстановление экрана/ввода, проверка отсутствия sleep inhibitors, сценарий USB и кнопка возврата. Перед USB mass storage выходить из сторонних приложений согласно предупреждениям KOReader.

Если standalone-приложение перестало отвечать, сначала штатное закрытие/перезапуск по инструкции Amazon для конкретной модели. Не сбрасывать устройство и не перепрошивать автоматически. Поскольку проект не устанавливает autostart и не меняет системные файлы, удаление его отдельной пользовательской папки после завершения процессов должно быть достаточным откатом приложения. Это не гарантия восстановления после стороннего jailbreak; соответствующие инструкции и риски остаются у выбранного метода.
