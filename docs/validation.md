## Проверки на PW4 13.11.2026

Статические ARMv7 hard-float бинарники собраны Zig 0.13.0 с musl и libc++.
Архив компилятора проверен по SHA256 из официального download index Zig.
`scripts/build-arm.ps1` воспроизводит сборку CLI и тестов на Windows.
Оба бинарника перенесены через SFTP по USB в `/mnt/us/kindle-lite`.

На самом PW4 `core_tests` завершился с `36 checks passed`. Через ARM CLI
проверены построение индекса, выборка и чтение русского UTF-8 TXT. Длительности
одиночного запуска для одной тестовой книги составили 5928, 3457 и 3002 мкс
соответственно. Это проверка запуска и функций, без сравнительного benchmark.

Первый снимок штатной системы показал MemAvailable около 195212 kB, RSS cvm
115712 kB, KPPMainApp 59560 kB и mesquite 40344 kB. RSS процессов может включать
общие страницы, складывать эти числа как расход физической памяти нельзя.
Сырой снимок хранится локально в `runtime/device-baseline` и исключён из Git.
`tools/capture-baseline.ps1` повторяет сбор снимка.

Подтверждены экран 1072×1448, framebuffer 8 bpp с виртуальным буфером
1088×6144 и сенсор goodix-ts на event2 конкретного экземпляра. Привязка к event2
не переносится автоматически на другие Kindle. Графический backend реализован
через FBInk и evdev; пользователь подтвердил физическое перелистывание.

## Методика сравнения на устройстве

### Обновление 14.11.2026

Windows CTest: 4/4. PW4: 51 core, 12 document, 13 web checks.
Нативные formats-smoke и browser-follow-smoke завершились кодом 0.
Проверены EPUB/FB2, страницы и сохранённая закладка; HTTPS IANA, 31 ссылка,
переход на главную (36 ссылок), история и экранная клавиатура. Снимки framebuffer
браузера и FB2 просмотрены на ПК. Это программная подача координат обработчику;
физическое использование новых кнопок пользователем пока не подтверждено.

С работающим power bridge powerd перешёл в screenSaver, затем active;
получены оба события, UI перерисован после wake. Тест выполнен по USB,
не доказывает глубокий сон и экономию батареи.

Отдельный autostart job успешно запущен через start kindle-lite. Затем выполнена
настоящая перезагрузка. После восстановления SSH uptime составлял 225 секунд,
guard в /tmp создан в текущем boot, boot.log обновлён после загрузки и содержит
SESSION/PAINT, физические касания вкладок, открытие книги и TAP x=893 y=65,
после которого восстановлен lab126_gui. Повторного автоматического входа не было.
Таким образом, автозапуск и физический выход кнопкой Amazon подтверждены.
Ранний вывод о неудаче по одному экрану Amazon был ошибочным: журнал показывает,
что до этого новая среда уже работала и была закрыта через свою кнопку.

Одинаковые устройство/FW, заряд/температура, подсветка, Wi-Fi, набор книг и последовательность действий. Отдельно холодный/тёплый кеш, минимум 10 повторов запуска/открытия. Не чистить системный кеш и не менять CPU governor для одного варианта. Чередовать порядок Amazon/прототип; фиксировать медиану, p95, ошибки и условия.

| Метрика | Метод | Текущий статус |
| --- | --- | --- |
| Запуск UI | monotonic timestamp до запуска и после первого paint + видео | Инструментирование первого paint ещё нужно |
| Открытие каталога/книги | CLI elapsed_us; GUI timestamp от действия до paint | CLI доступен, аппаратных замеров нет |
| RAM | /proc/PID/status: VmRSS/VmHWM; Windows CSV отдельно | Windows samples получены |
| CPU | delta /proc/PID/stat за заданный интервал, учесть CLK_TCK | Kindle сборщик ещё нужен |
| Wakeups | perf/powertop только если уже доступны; указать влияние измерителя | Не измерено |
| Сон/пробуждение | штатные события power backend + monotonic timestamps и внешняя проверка | Не измерено |
| Батарея | не менее 24–72 ч покоя, сопоставимый цикл чтения, несколько повторов | Не измерено |

Процент заряда дискретен и зависит от калибровки. Для малых отличий нужен внешний измеритель с корректной методикой: USB-питание само меняет режимы сна/заряда. Сбор логов и периодический опрос могут мешать глубокому сну; на sleep-тестах использовать минимальную событийную регистрацию. Не сравнивать Windows working set с Kindle RSS и не выводить автономность из размера exe.
