# Исследование PW4

> Исторические заметки первоначального исследования. Текущее проверенное
> состояние устройства и принятые решения: [current-device.md](current-device.md).

Дата проверки источников: 12 ноября 2026. Документ отделяет данные upstream от наблюдений на конкретном устройстве, которых пока нет.

## Подтверждено первичными источниками

1. [Пресс-релиз Amazon от 16.10.2018](https://press.aboutamazon.com/2018/10/meet-the-all-new-kindle-paperwhite-thinner-lighter-2x-the-storage-and-waterproof-for-just-129) подтверждает шестидюймовую панель 300 ppi, подсветку и варианты памяти 8/32 ГБ. Это не подтверждение SoC или RAM.
2. [Kindle backend KOReader](https://github.com/koreader/koreader/blob/master/frontend/device/kindle/device.lua) содержит модель `KindlePaperWhite4`, `display_dpi = 300`, touch/frontlight и семейство Rex. В комментариях различаются Wi-Fi и LTE input devices: нельзя фиксировать event2 для всех экземпляров. Тот же backend определяет hard-float по наличию `/lib/ld-linux-armhf.so.3`.
3. [Инструкция установки KOReader](https://github.com/koreader/koreader/wiki/Installation-on-Kindle-devices) указывает `kindlehf` для FW >= 5.16.3 и KUALA для новых прошивок; старую инструкцию KUAL нельзя безусловно применять к 5.16.7. Способ запуска также зависит от уже используемого jailbreak. Документация отдельно предупреждает о переходе в USBMS при работающем KOReader.
4. [koreader-base](https://github.com/koreader/koreader-base) объединяет Lua-окружение и существующие движки MuPDF/CREngine и другие библиотеки. Это не небольшая универсальная C-библиотека с готовым стабильным ABI. Выбран путь будущей интеграции через штатный KOReader frontend/backend, а не выдуманный API.
5. [FBInk](https://github.com/NiLuJe/FBInk) предоставляет библиотеку/CLI для e-ink framebuffer. Предпочтительный кандидат вместо самостоятельного копирования ioctl-структур. Наличие библиотеки на устройстве и совместимость выбранной сборки ещё нужно проверить.
6. [WinterBreak](https://kindlemodding.org/jailbreaking/WinterBreak/) указывает запрет для FW 5.18.1 и выше и требует поддерживаемую зарегистрированную модель, выбранную wizard. 5.16.7 ниже этого порога, но **это само по себе не подтверждает возможность jailbreak конкретного устройства**.
7. [Jailbreaking Wizard](https://kindlemodding.org/jailbreak-wizard.html) запрашивает префикс серийного номера, прошивку, возможность регистрации и рекламу на lockscreen. Эти сведения пользователя отсутствуют. Совместимость остаётся условной; автоматических действий нет.

## Не подтверждено на устройстве

SoC i.MX6 SoloLite/Cortex-A9 и 512 МБ RAM из задания остаются входными гипотезами: перед выбором CPU flags нужны `/proc/cpuinfo`, `/proc/meminfo` и сведения о плате. Не следует смешивать варианты SoloLite и SoloLite Lite по названию. Разрешение 1072×1448 используется только как целевой ориентир симулятора, физический framebuffer нужно прочитать отдельно. Размер окна Windows 576×808 — самостоятельный уменьшенный макет, не точный pixel mapping.

Неизвестны: loader/ABI установленной FW, версия libc/libstdc++, доступный sysroot, формат framebuffer и waveform, touch rotation/slot protocol, прошивочные свойства LIPC, USB-события, допустимые inhibit/restore последовательности сна и состояние jailbreak. ARM toolchain не установлен; WSL отсутствует. Страница Amazon с исходниками GPL при проверке вернула HTTP 503; исходники конкретного firmware не получены. Нельзя объявлять ядро/драйверы изученными на основании одной модели устройства.

## Аппаратные интерфейсы как кандидаты

KOReader использует LIPC-сервисы `com.lab126.wifid` и `com.lab126.cmd` для сети, события wifid для изменений состояния. Это подтверждает подход upstream, но не разрешает копировать команды вслепую. Для начального этапа сохраняются штатные службы; собственные управление сетью и сон не подключены.

Для ввода и экрана сначала read-only probe, затем адаптер проверенной библиотеки. Параметры питания/CPU не меняются. Частичные обновления требуют натурной проверки ghosting и стабильности; модель RefreshPolicy — только логика выбора, не драйвер.

## Браузер и лицензии

Полноценный web engine существенно расширяет зависимости и расходы памяти. Первый реализованный вариант — текстовый HTTPS-клиент Windows, не ARM backend. Для Kindle следует отдельно исследовать libcurl с актуальным TLS/CA bundle и простой HTML parser; перенос WinHTTP невозможен. Links/NetSurf и готовые web engines пока не собраны и не проверены. Поддержка современных сайтов не заявляется.

При интеграции KOReader/движков/FBInk нужны фиксация версий, проверка лицензий и обязательств при распространении. Сейчас сторонний код и бинарники в репозиторий не включались.
