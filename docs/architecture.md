# Архитектура

`kindle_core` — переносимая C++17 библиотека без GUI/сетевых зависимостей. `kindle_sim` — Win32/GDI backend. `kindle_cli` и тесты используют то же ядро. Основная оболочка не использует browser runtime или Electron.

| Компонент | Реализация | Граница |
| --- | --- | --- |
| library | Дисковый каталог записей, явный streaming scan | Метаданные пока из имён файлов |
| reader | Ограниченная TXT-страница, UTF-8 codepoint wrapping | Не замена KOReader |
| core/state | Прогресс по пути, одна закладка, настройки | Один писатель; временный файл и replace |
| ui | Win32 message loop / GDI | Windows-only, ожидает GetMessage |
| browser | WinHTTP в отдельном потоке, HTML в текст | Windows-only, 2 МиБ на ответ |
| eink | Политика full/partial/none | Не подключена к экрану |
| power/wifi | Проверяемая idle policy и явно demo-параметры | Аппаратных эффектов нет |

## Память и операции

Индекс хранится на диске. Для страницы каталог читается последовательно; в памяти удерживается максимум девять кандидатов и затем восемь результатов. Стоимость выбора O(N), память O(размера страницы). Это простой первый компромисс: большие библиотеки потребуют измерений и возможной замены на SQLite с индексами и keyset pagination. Повторное сканирование файловой системы происходит только при обновлении каталога.

Reader держит одну страницу; назад используются byte offsets текущего сеанса. История сейчас растёт с числом перелистываний и не хранит тексты страниц. Настройки геометрии меняют разбивку при следующем открытии, сохранённый byte offset остаётся точкой начала. Одна закладка на книгу — ограничение прототипа.

На Windows состояние заменяется MoveFileEx с WRITE_THROUGH. На Linux используется rename: это атомарная видимость, но без fsync нельзя обещать сохранность последней записи при обрыве питания. Каталог Windows имеет промежуточный `.old`: при падении между rename потребуется ручное восстановление либо пересоздание индекса. Эти ограничения нужно устранить до аппаратного релиза.

GUI не использует таймеры, фоновых обходов нет. HTTPS выполняется только по явному нажатию; UI продолжает обрабатывать события. Закрытие во время запроса откладывается, отмена не реализована. Истёкший deadline проверяется между чтениями, поэтому одна блокирующая операция может завершиться позднее deadline на свой timeout. Дескрипторы освобождаются RAII.

## Следующая интеграция

Переиспользовать Kindle backend KOReader для lifecycle, touch, power и чтения форматов. Для бесшовной оболочки предпочтительно отдельное расширение frontend с тремя основными разделами либо формально согласованный lifecycle внешнего приложения. Текущий standalone TXT-прототип не выдаётся за такую интеграцию. Прямое подключение CREngine/MuPDF потребует собственного layout, кешей, лицензирования и тестирования; это пока не выбранный путь.
